# 0. 왜 "열심히"가 배신하는가

```
한국 수능 패러다임     미국 대학 패러다임
────────────────       ────────────────────
정해진 범위 → 암기     읽어 오기 → 토론 → 적용
선생님이 정리해줌       교수는 방향만 제시
시험이 학습의 끝       시험은 중간 체크포인트
혼자 밤새 공부         스터디그룹 + Office Hours
정답 맞히기            근거 있는 주장 세우기
```

- 한국식 무기: **속도·암기·패턴**
- 미국 대학에서 필요한 무기: **독해력·논증·자기관리**

🎓 **Ivy Tip**: 새로운 게임에서 이기려면 **규칙부터 새로 읽어야 한다.** 미국 대학 첫 학기의 충격은 거의 다 여기서 온다.

# 0-1. 패러다임 전환 비용 (도표)

| 상황 | 한국식으로 버티면 | 미국식으로 전환하면 |
|---|---|---|
| 리딩 숙제 100쪽 | 다 읽고 암기 → 탈진 | 논지 파악에 집중 → 40분 |
| 에세이 과제 | 내용 채우기 급급 | 주장→근거→반론 구조 먼저 |
| 토론 수업 | 모범 답안 기다림 | 내 의견 먼저, 수정은 나중에 |
| 시험 전날 | 올나이터 암기 | 이미 복습 3회 완료 |
| Office Hours | 안 감 (눈치 보임) | 교수와 1:1 면담 루틴 |

> 전환하는 데 평균 **한 학기.** 미리 알면 **첫날부터** 다르다.

# 강의 12 · 미국 대학 수업 구조 해부

**정의:** 미국 대학 수업은 단일 "수업" 하나가 아니라 **여러 형식의 조합**이다.

```
┌─────────────────────────────────────────────┐
│  Lecture  (대형 강의, 100~500명)             │
│   ↓  "무엇을" 배우나 — 개념·프레임 제공      │
├─────────────────────────────────────────────┤
│  Reading  (사전 독서, 주 1~3회)              │
│   ↓  "진짜 학습"은 여기서 일어남             │
├─────────────────────────────────────────────┤
│  Section / Discussion (20명 이하 소그룹)     │
│   ↓  개념 적용·토론·TA 보정                 │
├─────────────────────────────────────────────┤
│  Problem Set / Essay / Lab (과제)            │
│   ↓  산출 → 진짜 이해 확인                  │
├─────────────────────────────────────────────┤
│  Office Hours (교수·TA 1:1)                 │
│   ↓  막힌 곳 보정 + 관계 형성               │
└─────────────────────────────────────────────┘
```

---

# 12-1. 각 형식의 역할과 활용 전략

| 형식 | 시간 비중 | 올바른 목적 | 흔한 실수 |
|---|---|---|---|
| Lecture | 2~3h/주 | 구조 파악·질문 수집 | 받아 적기에 급급 |
| Reading | 4~8h/주 | 논지 파악·메모 | 처음부터 줄줄 읽기 |
| Section | 1h/주 | 질문 소비·의견 말하기 | 침묵·존재감 없음 |
| Pset/Essay | 5~10h/주 | 개념 적용·논증 연습 | 답 맞추기에 집중 |
| Office Hours | 선택 | 관계·보정·추천서 | 아예 안 감 |

🎓 **Ivy Tip**: Reading을 **Lecture 전에** 끝내라 — 강의가 2배 빠르게 들린다. 코넬·하버드 학생 대부분이 이 순서를 지킨다.

---

# 12-2. Reading 속공법 — SQ3R 변형

**왜:** 주 100쪽 이상 읽어야 할 때 처음부터 줄줄 읽으면 탈진한다.

```
Survey  (5분)  제목·소제목·그림·요약 훑기 → "이 챕터가 뭘 주장하나?"
Question(2분)  소제목을 질문으로 변환     → "왜 X는 Y인가?"
Read    (집중) 질문에 답하며 읽기          → 속도 2배
Recite  (즉시) 책 덮고 핵심 3줄 기억      → 기억 고착
Review  (1일 후) 내 메모만 보고 재구성   → 장기화
```

✍️ 실습: 다음 Reading 과제에서 SQ3R 한 번만 써봐라. **읽는 시간 30% 단축**을 체감한다.

`[그림: SQ3R 단계별 타임라인 — 50쪽 챕터를 40분에 처리하는 예시]`

# 12-3. Office Hours — 대부분이 버리는 황금 자원

**왜 안 가나:**
- "질문 없으면 민폐" (❌ 틀림 — 교수는 오는 학생을 기다린다)
- "바빠 보임" (❌ — Office Hours는 교수가 비워둔 시간)
- "학점 잘 받고 있음" (❌ — 추천서는 아는 교수에게서 나온다)

**가야 하는 이유 3가지**
1. **개념 보정**: 혼자 잘못 이해한 것을 1분에 고친다.
2. **성적 협상**: 에세이 피드백 → 재채점 요청 근거.
3. **추천서·인턴**: 3년 후 "아 그 학생" 되려면 지금부터.

🎓 **Ivy Tip**: 첫 번째 Office Hours에서 할 말: **"Professor, 이번 Reading에서 X 개념이 Y와 어떻게 다른지 헷갈렸습니다 — 맞게 이해한 건가요?"** 이거면 충분하다.

# 강의 13 · 교수는 무엇을 평가하는가

**정의:** 미국 대학 교수의 채점 기준은 **"맞냐"가 아니라 "어떻게 생각했냐"**다.

```
한국식 채점 기준        미국 대학 채점 기준
─────────────          ──────────────────
정답 여부              논증의 구조
외운 내용량            개념 적용 능력
빠른 계산              가정·한계 인식
암기 정확도            독창적 관점
```

**4대 평가 축 (거의 모든 과목 공통)**
| 평가 축 | 체감 비중 | 핵심 질문 |
|---|---|---|
| 개념 이해 | ★★★ | 정의를 **자기 말로** 설명할 수 있나? |
| 적용·분석 | ★★★★ | 새 상황에 개념을 **사용**할 수 있나? |
| 논증 구조 | ★★★★ | 주장 → 근거 → 반론 처리가 되나? |
| 독창성 | ★★★ | 교수가 "오, 그 시각은 처음이다"를 느끼나? |

---

# 13-1. 루브릭(Rubric) 해독법

**루브릭이란:** 교수가 미리 공개하는 **채점 기준표**. 답이 여기 있다.

```
항목               4 (Excellent)          2 (Developing)
─────────────────  ─────────────────────  ──────────────────
Thesis             명확·논쟁가능·구체적  있지만 모호함
Evidence           다양·직접 연결         열거만 함
Analysis           깊이·다층적 해석       요약에 그침
Counterargument    다루고 반박함          언급 없음
Clarity            정확·간결              어색·모호
```

**루브릭 사용 순서:**
1. 과제 받자마자 루브릭 **먼저** 읽는다.
2. 각 항목을 **체크리스트**로 쓴다.
3. 제출 전 루브릭과 내 답안을 **한 줄씩 대조**한다.

🎓 **Ivy Tip**: 루브릭 없이 제출하는 건 지도 없이 등산하는 것. 프린트해서 옆에 두고 써라.

---

# 13-2. 📂 실물 — 하버드 Writing 루브릭 분석

`[그림: Harvard Expos 실제 루브릭 PDF 발췌 — Thesis/Evidence/Analysis/Counterargument 4항목, 각 4점 척도]`

**분석 포인트:**
- "Excellent" 칸의 **동사**를 봐라: *analyzes, synthesizes, anticipates, interrogates* — 모두 **능동적 사고** 동사.
- "Developing" 칸: *lists, describes, mentions, summarizes* — **수동적 나열** 동사.

> 한 줄 규칙: **묘사(describe) → 분석(analyze)** 로 바꾸면 B가 A가 된다.

✍️ 실습: 지금까지 낸 에세이 하나를 꺼내 위 동사 기준으로 분류해봐라.

# 13-3. 과목별 평가 차이 — 이과 vs 문과

| | STEM 과목 | 인문·사회 과목 |
|---|---|---|
| 핵심 증거 | 데이터·수식·실험 | 텍스트·사례·통계 |
| 논증 형식 | 가설→실험→결론 | 주장→근거→반론 |
| 독창성 발휘 | 풀이 경로의 우아함 | 해석 관점의 신선함 |
| 흔한 실수 ❌ | 답만 쓰고 과정 생략 | 근거 없는 주장 |
| 빠른 점수 ↑ | 단위·가정 명시 | 반론 1문단 추가 |

🎓 **Ivy Tip**: STEM도 **서술이 중요**하다. MIT Pset에서 "왜 이 방법을 택했나"를 1줄 쓰면 partial credit을 구한다.

# 강의 14 · 시험보다 중요한 것

**정의:** GPA는 입장권이다. **산출물(Output)**이 차별점이다.

```
GPA 3.9 + 산출물 없음   →  "우등생"
GPA 3.7 + 산출물 있음   →  "만든 사람" (연구·인턴·추천서 유리)
GPA 4.0 + 산출물 없음   →  대학원 인터뷰에서 할 말 없음
GPA 3.5 + 저널 논문 1편 →  대학원 합격
```

**산출물의 4가지 형태**
| 형태 | 예시 | 만드는 시점 |
|---|---|---|
| 글 | 블로그·논문·에세이집 | 학기 중 |
| 코드 | GitHub 프로젝트·앱 | 방학+주말 |
| 연구 | 교수 랩 RA·논문 공저 | 2~3학년 |
| 이벤트 | 컨퍼런스·경진대회·클럽 | 1학년~|

---

# 14-1. 산출물이 시험보다 중요한 이유 (3가지)

**1. 기억의 자연 감쇠**
```
시험 직후     시험 2주 뒤   시험 1년 뒤
   100%    →    40%      →    10%
   (기억)        (기억)        (기억)
산출물은 1년 뒤도 GitHub·Drive에 남아있다.
```

**2. 증명의 차이**
- 시험: "나는 외웠다" 증명
- 산출물: "나는 *쓸 수 있다*" 증명

**3. 네트워크 효과**
- 블로그 포스트 → 교수 눈에 띔 → 랩 RA 제안
- GitHub 프로젝트 → 인터뷰 포트폴리오
- 컨퍼런스 발표 → 동료 연구자 네트워크

🎓 **Ivy Tip**: 코넬 CS 출신들이 인터뷰에서 가장 먼저 보여주는 건 성적표가 아니라 **GitHub 링크**다.

---

# 14-2. 학기 중 산출물 만드는 루틴 (도해)

```
월요일 강의 → [메모 10분]
화요일 Reading → [궁금한 점 기록]
수요일 Section → [토론에서 나온 새 관점 추가]
목요일 복습 + [블로그 초안 200자]
금요일 Pset 제출 → [이 과정에서 배운 것 → GitHub README]
토요일 [주 1회 micro-output: 블로그·노트·코드]
일요일 휴식
```

> 주당 1개 micro-output → 학기당 15개 → 4년간 **120개** 산출물 포트폴리오.

✍️ 실습: 지금 배우고 있는 과목 하나에서 "이번 학기 끝날 때 손에 남길 것" **1가지**를 적어봐라.

# 14-3. 📂 실물 — 프린스턴 학생의 산출물 포트폴리오

`[그림: 프린스턴 CS 3학년 학생의 GitHub Profile — 핀 고정 레포 6개: 1학년 소규모 CLI 도구, 2학년 웹앱, 3학년 랩 연구 코드, 개인 블로그 링크]`

**포인트:**
- 1학년 레포: 간단한 To-do CLI — **코드 50줄**도 시작이다.
- 2학년: 수업 Pset 확장판 → 개인 프로젝트로 전환.
- 3학년: 지도교수와 공동 레포 — 논문 제출 중.

> "처음부터 대단한 것을 만들어야 한다"는 **환상**이다. 학기마다 이전 것을 **한 단계** 키우면 된다.

# 강의 15 · 학습 시스템 설계 — Personal Academic OS

**정의:** Personal Academic OS = 공부의 **흐름을 자동화하는 4층 구조.**

```
┌──────────────────────────────────────────────┐
│ 4층  Output (산출)                            │
│      → 블로그·GitHub·노트·에세이 최종본       │
├──────────────────────────────────────────────┤
│ 3층  Review (복습)                            │
│      → Active Recall + 간격반복(Spaced Rep)   │
├──────────────────────────────────────────────┤
│ 2층  Capture (정리)                           │
│      → 코넬노트·Notion·개념 지도              │
├──────────────────────────────────────────────┤
│ 1층  Input (입력)                             │
│      → 강의·교과서·논문·YouTube               │
└──────────────────────────────────────────────┘
```

> 대부분의 학생은 **1층만** 한다. Ivy급은 **2~4층이 두껍다.**

---

# 15-1. 4층 각각 : 역할·도구·시간 배분

| 층 | 역할 | 추천 도구 | 주당 시간 |
|---|---|---|---|
| 1층 Input | 개념 첫 만남 | 강의노트, 교과서, Zotero | 8~12h |
| 2층 Capture | 내 말로 정리 | Cornell Note, Notion DB | 3~5h |
| 3층 Review | 기억 고착·연결 | Anki, self-quiz, 친구 설명 | 2~3h |
| 4층 Output | 증명·공유 | GitHub, 블로그, Drive | 2~4h |

🎓 **Ivy Tip**: 시간이 없을 때 가장 먼저 **2층(정리)부터 지키라.** 1층은 강의가 강제하지만, 2층이 없으면 1층이 물처럼 빠진다.

---

# 15-2. Academic OS 4개 기둥 — 도구 세팅법

| 기둥 | 역할 | 추천 도구 | 세팅 포인트 |
|---|---|---|---|
| Capture | 입력 → 정리 | Notion, Obsidian, 손노트 | 과목별 DB 1개씩 |
| Organize | 자료 분류 | Google Drive, Zotero | 폴더: 과목/주차/유형 |
| Schedule | 단계 배치 | Google Calendar, Notion | 공부 "단계" 블록 색구분 |
| Review | 장기 기억 | Anki, RemNote, self-quiz | 덱은 과목당 1개, 매일 10분 |

```
Notion DB 예시 구조:
  [과목] → [주차] → [강의/Reading] → [핵심 개념] → [내 질문] → [Anki 링크]
```

✍️ 실습: 지금 사용하는 앱/방법을 4기둥에 하나씩 매핑해봐라. **빈 기둥이 약점**이다.

# 15-5. Anki + 간격반복 — 30분 만에 세팅하는 법

**왜 Anki인가:**
```
1회 복습   → 기억 70%
간격반복   → 기억 90%+ (6개월 후)
밑줄만     → 기억 30%  (1주 후)
```

**세팅 3단계:**
1. **덱 구조**: 과목 1개 = 덱 1개 (세분화 ❌, 나중에 찾기 어려움)
2. **카드 원칙**: 앞 = 개념/질문, 뒤 = 예시+내 말로 설명 (교과서 문장 복붙 ❌)
3. **루틴**: 매일 아침 10분, 알림 설정, 드는 카드는 EASY, 헷갈리는 건 HARD

🎓 **Ivy Tip**: 카드 1장 만드는 데 **30초**. 수업 끝나고 주요 개념 5개 → 5장. 한 학기 = 약 300장 = 시험 전날 새 공부 없음.

**Q. 과목이 5개인데 Anki 덱 다 만들어야 하나요?**
A. 아니다. 지금 가장 외울 게 많은 과목 **1개**만 먼저. 나머지는 확장.
