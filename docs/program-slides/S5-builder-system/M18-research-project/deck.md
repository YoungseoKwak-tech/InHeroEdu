
# 1. 강의 74 · 독립 연구란 무엇인가

## 고등학생이 할 수 있는 연구 유형 4가지

| 유형 | 설명 | 예시 | 필요 자원 |
|---|---|---|---|
| **실험 연구** | 변수 통제 후 실험 | 비타민C 산화 속도 측정 | 학교 실험실 |

# 1-1. 좋은 연구 질문 만들기 — 3단계

```
Step 1 · BROAD   "나는 [주제]에 관심 있다"
                         ↓
Step 2 · NARROW  "그중에서도 [특정 집단/지역/기간]이 궁금하다"
                         ↓
Step 3 · RQ      "X가 Y에 미치는 영향은 무엇인가?
                  (in context Z, using method M)"
```

**좋은 RQ 체크리스트**
- [ ] 답을 *찾을 수 있는가* (Answerable)?
- [ ] 내가 *실제로 데이터를 모을 수 있는가* (Feasible)?
- [ ] 이미 완벽히 답된 질문은 아닌가 (Novel)?
- [ ] 결과가 누군가에게 *의미 있는가* (Relevant)?

# 1-2. RQ — 📝 채워진 예시 3개

| 관심 영역 | 나쁜 RQ ❌ | 좋은 RQ ✅ |
|---|---|---|
| 환경 | "기후변화가 나쁜가?" | "서울 25개 구 녹지율과 여름 평균기온 간 상관관계(2010–2023)" |
| 심리 | "스마트폰이 해로운가?" | "고등학생 수면 전 스마트폰 사용 시간과 다음날 집중력 자기보고 점수 관계" |
| 생명과학 | "항생제 내성이 문제다" | "세 종류 항균 비누 농도별 대장균 콜로니 형성 억제 효과" |

🎓 **Ivy Tip**: RQ는 *논문 제목 초안*이기도 하다. 제목만 봐도 무엇을 했는지 알면 좋은 RQ.

# 1-3. RQ 심화 — 아이비 수준이 되는 질문의 조건

**단순 RQ vs. 아이비 수준 RQ 비교**

| 수준 | 예시 |
|---|---|
| 일반 | "유튜브 시청이 수면에 영향을 미치는가?" |
| 중급 | "한국 고등학생의 심야 유튜브 시청 시간과 다음날 수면 후 자기보고 인지 기능 점수의 관계" |
| 아이비 수준 | "수면 전 60분 이상 유튜브 시청군(n=43) vs. 비시청군(n=44)에서 Pittsburgh Sleep Quality Index(PSQI) 점수 차이 및 청색광 차단 안경 중재 효과: 단일맹검 교차설계(crossover design)" |

**핵심**: 집단·측정 도구·비교 조건·설계 방식을 RQ 안에 넣을수록 심사 가능한 연구가 된다.

🎓 **Ivy Tip (예일 신경과학 전공 재학생, 2024 인터뷰)**: *"Pittsburgh Sleep Quality Index는 논문에 무조건 넣어요. 출처가 있는 검증된 도구를 쓴다는 것 자체가 신뢰도예요. 제가 직접 만든 '수면 점수'보다 훨씬 낫죠."*

# 1-4. 흔한 실수 ❌ & FAQ — 연구 주제 선정

**흔한 실수 ❌**
- RQ가 너무 넓음 → "암의 원인" → "폐암 발생률과 해당 지역 PM2.5 농도 상관"으로 좁혀라
- 답이 이미 정해진 질문 → "담배가 해롭다는 걸 증명" → 탐구가 아니라 확인
- 자원 초과 → MRI가 필요한 실험, 5,000명 설문 → 현실 가능한 규모로

**FAQ**
**Q. 독창적이어야 하나?**
A. 완전히 새로운 발견 필요 없다. *내 지역/학교/맥락*에 적용하는 것으로도 충분.

**Q. 지도 교수가 없으면?**
A. 국내 대학 연구실 콜드 메일, 지역 과학관, 학교 선생님 → 셋 중 하나는 연결된다.

# 1-5. 콜드 메일 실전 — 대학 교수·연구소 접촉 전략

**보내야 하는 대상**
- 해당 RQ와 같은 주제 논문 저자 (Google Scholar → 대학 이메일 검색)
- 국내: KAIST·포항공대·연세·고려 연구실, 한국환경연구원(KEI), 한국청소년정책연구원
- 해외: ResearchGate 프로필에 이메일 공개된 교수

**콜드 메일 3문단 공식**
```
문단 1 (2줄): 나는 누구, 어느 학교, 몇 학년
문단 2 (3줄): 교수님 논문 [제목] 읽었고, 이 부분이 [내 RQ]와 연결됨
문단 3 (2줄): 구체적 요청 — "30분 화상 미팅" 또는 "이메일 피드백"
              → 데이터 수집 무결성 서약서 첨부 의향 언급
```

🎓 **Ivy Tip**: 콜드 메일 응답률 평균 8–12%. **20명에게 보내야 2–3명 답장**. 처음 5명이 안 답해도 정상. 보낸 이력 자체가 에세이 소재다.

# 1-6. 🎓 실전 꿀팁 모음 — 연구 질문 & 시작

- **Pittsburgh Sleep Quality Index(PSQI), PHQ-9, GAD-7** 같은 공인 심리·건강 척도를 RQ에 쓰면 측정 신뢰도가 즉시 올라간다. 구글폼에 그대로 넣어도 됨.
- **Google Scholar Alert** 설정: 내 RQ 키워드 → 메일 알림 → 새 논문 자동 수신. 10학년부터 켜두면 11학년엔 배경지식이 쌓임.
- 연구 주제는 **본인 학교 데이터**로 좁혀도 강력함. "우리 학교 1–3학년 347명 설문"은 접근 가능하고 독창성도 있음.
- 국제학생이면 **한국 vs. 타국 비교 RQ**가 쉽게 차별화됨. (예: 한국 고등학생 수면 vs. OECD 평균 비교 분석)
- 콜드 메일 보낼 때 **교수 논문의 구체적 Table 번호·수치 언급** → 진짜 읽었다는 신호. 응답률 2–3배 상승.
- 연구 시작 첫날부터 **Research Journal(노션·종이 일기)** 작성. 날짜·결정 이유·막힌 지점 기록 → 에세이 소재 자동 생성.
- **ResearchGate**에 학생 계정 만들어 관심 저자 팔로우 → 신규 preprint 알림 받기.
- 주제가 안 잡히면 **학교 수업 중 가장 궁금했던 것 3개**를 적고 Feasible 필터 적용 → 하나는 반드시 살아남는다.

# 2. 강의 75 · 문헌조사 워크플로우

## 왜 문헌조사가 먼저인가

```
내가 연구하기 전에 → 이미 누가 연구했나?
                    → 그들이 쓴 방법은?
                    → 빈 구멍(Gap)은 어디인가?
                                 ↓
                    내 연구가 그 Gap을 채운다
```

**3가지 역할**
1. **중복 방지** — 이미 완벽히 답된 질문인지 확인
2. **방법 학습** — 선행 연구 방법론을 내 연구에 적용
3. **근거 제공** — Introduction/Discussion에서 인용

---

# 2-1. 신뢰할 수 있는 소스 계층

```
★★★ 최우선
  └─ Google Scholar (scholar.google.com)
  └─ PubMed (biomedical)
  └─ JSTOR (인문·사회)
  └─ arXiv (물리·CS·수학 preprint)

★★  2차 소스
  └─ 학교 도서관 DB (RISS, KISS, DBpia)
  └─ 정부 공개 데이터 (통계청, 교육부, WHO)

★   최후 수단
  └─ Wikipedia (개요 파악만, 절대 인용 금지)
  └─ 뉴스 기사 (팩트 확인용, 학문적 인용 금지)
```

🎓 **Ivy Tip**: 논문 한 편의 **참고문헌 리스트**를 역추적하면 핵심 선행연구 10편이 한꺼번에 나온다 — "Snowball 전략."

# 2-4. Boolean 검색 + 필터 심화

```
나쁜 검색:   "스마트폰과 수면"

좋은 검색:   ("smartphone" OR "mobile phone") AND "sleep quality"
              AND ("adolescent" OR "teenager") AND "Korea"
              → 필터: Since 2020, Article type: Randomized Controlled Trial

더 좋은 검색: TITLE:("sleep quality") AND ("Pittsburgh Sleep Quality Index"
              OR "PSQI") AND ("Korean" OR "South Korea")
              → PubMed에서 TIAB 필드 지정 검색
```

**Google Scholar 고급 기능**
- `site:pubmed.ncbi.nlm.nih.gov [키워드]` → PubMed만 검색
- `filetype:pdf [논문 제목]` → PDF 직접 접근
- "Cited by N" 클릭 → 해당 논문을 인용한 최신 연구 확인

🎓 **Ivy Tip**: 검색 키워드를 **영어+한국어 동시**로 돌려라. 국내 RISS에 한국어 논문이, Google Scholar에 영어 번역본이 따로 있는 경우가 많다.

# 2-5. 문헌 요약표 — 고급 분석 열 추가

**기본 7열 외 추가하면 좋은 열**

| 추가 열 | 설명 | 왜 유용한가 |
|---|---|---|
| **샘플 크기 (n)** | 피험자 수 | 내 연구와 규모 비교 기준 |
| **측정 도구** | 사용한 척도·장비 이름 | 그대로 빌려 쓸 수 있음 |
| **통계 방법** | t-test, ANOVA, 회귀 등 | 내 분석 방법 참고 |
| **한계점** | 논문 자체 언급 한계 | 내 Gap 찾기 |
| **인용 횟수** | Google Scholar 기준 | 핵심 논문 여부 판별 |

# 3-5. 연구 설계 고급 — 교란변수와 통제 전략

**교란변수(Confounding Variable)를 다루는 3가지 방법**

```
방법 1: 통제 (Control)
  → 통제 변수로 처리해 Methods에 명시
  → 예: "고령 인구 비율이 다른 구는 별도 분류하여 분석"

방법 2: 다중 회귀 (Multiple Regression)
  → Python/R에서 여러 변수를 동시에 모형에 포함
  → 예: park_area, elderly_ratio, building_density → heatstroke (종속)

방법 3: 한계로 인정 (Limitation)
  → Discussion에서 "본 연구의 한계: X 변수를 통제하지 못했다"
  → 솔직하게 인정하는 것 자체가 학문적 성숙도의 증거
```

🎓 **Ivy Tip**: 다중 회귀를 쓰면 "독립변수만의 효과(partial effect)"를 격리할 수 있다. Python `statsmodels` 라이브러리로 고교생도 30분 안에 돌릴 수 있음.

# 3-6. 흔한 실수 ❌ — 실험·설계 단계

**흔한 실수 ❌**
- 통제변수 없이 "그냥 비교" → 결과가 다른 원인 때문일 수 있음
- 샘플 너무 작음 (n=5) → 통계적으로 의미 없음 → 설문 최소 30명, 실험 최소 3반복
- 가설을 결과 본 *후에* 작성 → **HARKing (Hypothesizing After Results Known)** — 비윤리적

**Q. 결과가 가설과 반대로 나왔어요.**
A. **훌륭하다.** 예상 밖 결과 = 더 흥미로운 논문. Discussion에서 이유를 분석하라. 가설을 바꾸지 마라.

# 3-7. 🎓 실전 꿀팁 모음 — 연구 설계

- **공개 척도 도구 목록**: PSQI(수면), PHQ-9(우울), GAD-7(불안), SF-36(건강), SAS(스마트폰 중독), NDVI(위성 식생 지수). 직접 만들지 말고 검증된 도구를 그대로 가져다 써라.
- **설문 배포 최소 n=30, 권장 n=50**. 30명 미만이면 Central Limit Theorem 가정이 흔들려 통계적 해석이 약해진다.
- 실험 반복(replication) 최소 3회: 생물 실험은 3회 반복 후 평균. 그래야 "우연한 결과"를 배제할 수 있다.
- **데이터 전처리 계획을 Methods에 사전 명시** (Pre-registration 개념). 이후 아웃라이어 제거해도 "방법대로 했다"는 근거가 됨.
- **Power Analysis**: 통계적 검증력(power=0.8)을 위해 필요한 샘플 수를 G*Power(무료 소프트웨어)로 계산 → Methods에 "샘플 크기 산정 근거" 한 줄 추가 → 심사관 감점 없음.
- IRB가 필요 없는 연구 유형: ① 2차 공개 데이터 분석 ② 익명 설문(개인 식별 정보 없음) ③ 본인만 대상인 실험. 이 세 가지로 설계하면 IRB 절차 없이 빠르게 시작 가능.
- **설문 플랫폼 비교**: 구글폼(무료, 익명 설정 가능) vs. SurveyMonkey(분석 기능 좋음, 무료 40문항 제한). 대부분 구글폼으로 충분.

# 4-3. Python 고급 — 다중 회귀 & 시각화

```python
import statsmodels.api as sm

# 독립변수 여러 개
X = df[["park_area", "elderly_ratio", "building_density"]]
X = sm.add_constant(X)
y = df["heatstroke"]

model = sm.OLS(y, X).fit()
print(model.summary())  # β 계수, p값, R², adj-R² 출력

# 잔차 플롯 (모형 적합성 확인)
residuals = model.resid
plt.scatter(model.fittedvalues, residuals, alpha=0.5)
plt.axhline(0, color='red', linestyle='--')
plt.xlabel("Fitted values")
plt.ylabel("Residuals")
plt.title("Residual Plot")
plt.savefig("residual_plot.png", dpi=300)
```

# 4-4. 결과 해석 — 통계 기초

| 지표 | 의미 | 논문에 쓰는 법 |
|---|---|---|
| r = 0.7 이상 | 강한 양의 상관 | "strong positive correlation (r=0.72)" |
| p < 0.05 | 통계적으로 유의 | "statistically significant (p=0.03)" |
| p ≥ 0.05 | 유의하지 않음 | "no significant correlation (p=0.12)" — 이것도 결과다 |
| R² = 0.5 | 변동의 50% 설명 | "park area explains 50% of variance" |
| Cohen's d | 효과 크기 | d=0.2(소), 0.5(중), 0.8(대) |

**⚠️ 주의**
- "상관관계 ≠ 인과관계"를 항상 Discussion에 명시
- p < 0.05 = 참 이 아님. "이 결과가 우연일 확률 5% 미만"

# 4-6. 흔한 실수 ❌ — 데이터 분석

**흔한 실수 ❌**
- 이상치(outlier) 제거하고 "언급 안 함" → 논문에 반드시 이유 기재
- 상관관계를 인과관계로 표현 → "X가 Y를 증가시킨다" → **"X는 Y와 양의 상관관계를 보였다"**
- 그래프 축 레이블·단위 없음 → 무의미한 그래프
- p값만 보고 효과 크기(effect size) 무시 → Cohen's d 또는 η² 추가

✍️ **실습**: 1개 핵심 변수쌍에 대해 상관계수 r, p값, 산점도 1개 완성 → 논문 Figure 1 후보.

# 5. 강의 78 · 논문 IMRAD 작성

## IMRAD 구조란

```
I — Introduction  (왜 이 연구를 했나)
M — Methods       (어떻게 했나)
R — Results       (무엇을 발견했나)
A — And
D — Discussion    (그게 무슨 의미인가)
    + References  (인용 목록)
    + Abstract    (100–250단어 요약, 마지막에 씀)
```

> 논문은 **서론부터 쓰지 않는다.**
> Methods → Results → Discussion → Introduction → Abstract 순서로 써라.

---

# 5-1. 각 섹션 작성 가이드

| 섹션 | 분량 | 핵심 질문 | 흔한 실수 |
|---|---|---|---|
| **Abstract** | 100–250단어 | 한 문단에 전체 요약 | 결과 없이 "~했다" |
| **Introduction** | 400–600단어 | 왜? Gap은? RQ는? | 배경만 길게, RQ 안 나옴 |
| **Methods** | 600–800단어 | 재현 가능한가? | 재현 불가능할 만큼 모호 |
| **Results** | 400–600단어 | 수치·그래프 | 해석 섞기 (Discussion 몫) |
| **Discussion** | 600–800단어 | 의미·한계·미래 | 결과 반복만, 해석 없음 |
| **References** | 10편 이상 | APA 또는 AMA 형식 | 형식 불일치 |

# 5-2. Introduction — CARS 모델 (학술적 서론 공식)

**CARS = Create A Research Space (Swales, 1990)**

```
Move 1 · 영역 확립 (Establishing a territory)
  → 이 주제가 중요한 이유 + 선행 연구 2–3편 인용

Move 2 · 틈새 확인 (Establishing a niche)
  → "그러나 [이 측면]은 아직 연구되지 않았다"
  → Gap 문장: "however," "nonetheless," "despite this,"

Move 3 · 틈새 점유 (Occupying the niche)
  → "본 연구는 [방법]으로 [집단]에서 [RQ]를 분석한다"
```

🎓 **Ivy Tip (프린스턴 영문학 전공, AP Research 경험)**: *"CARS 모델은 실제 Nature, Cell 논문 서론도 다 이 구조예요. 고등학생 논문에 이 구조 쓰면 바로 티 나요 — 좋은 쪽으로."*

# 5-3. Introduction — 📝 채워진 예시 (발췌)

> *"도시 열섬 현상은 지구 온난화와 함께 심화되고 있으며, 서울의 경우 2010년 이후 여름철 평균기온이 1.3°C 상승했다(Kim et al., 2022). 특히 녹지가 부족한 도심 지역에서 열사병 관련 응급 이송이 집중되는 것으로 보고되었으나(Lee, 2021), 자치구 단위에서 공원 면적과 열사병 발생 간의 정량적 관계를 분석한 연구는 드물다. 본 연구는 서울 25개 자치구의 1인당 공원 면적과 열사병 응급 이송 건수 간의 상관관계를 분석함으로써 이 공백을 메우고자 한다."*

**구조 분석**
- 문장 1–2: Move 1 (배경 + 선행 연구 인용)
- 문장 3: Move 2 ("드물다" = Gap)
- 문장 4: Move 3 ("본 연구는…" = RQ 선언)

# 5-4. Methods — 재현 가능하게 쓰는 법

**테스트 기준**: "이 Methods만 읽고 다른 사람이 똑같이 재현할 수 있는가?"

```
포함해야 할 6가지:
1. 참가자/데이터 출처
   → "서울 25개 자치구 2015–2022년 연도별 데이터
       (data.seoul.go.kr, data.go.kr)"

2. 변수 조작적 정의
   → "1인당 공원 면적: 자치구 총 공원 면적(㎡) ÷ 주민등록 인구"

3. 데이터 전처리
   → "결측치 3개 행 제거(전체의 1.7%); 이상치 Z>3.0 기준 2개 제외"

4. 분석 도구 + 버전
   → "Python 3.11, pandas 2.0, scipy 1.11, statsmodels 0.14"

5. 통계 방법 + 유의수준
   → "Pearson 상관 분석, 유의수준 α=0.05"

6. 윤리 검토
   → "2차 공개 데이터 사용, IRB 면제"
```

# 5-5. Discussion — 어떻게 쓰는가

```
Discussion 4단계 구조:

1. 핵심 발견 재진술
```

# 5-6. Discussion — 고급: 예상 밖 결과 다루기

**"결과가 가설과 달랐을 때" 쓰는 방법**

```
나쁜 버전:
"가설과 달리 유의한 상관이 발견되지 않았다. (끝)"

좋은 버전 (아이비 수준):
"예상과 달리 공원 면적과 열사병 이송 건수 간에
유의한 상관이 발견되지 않았다 (r=0.14, p=0.47).
이는 세 가지 원인으로 설명될 수 있다:
첫째, 본 연구의 관측 단위가 '구 평균'이므로
구 내부 불균등 분포를 반영하지 못했을 가능성이 있다.
둘째, 공원 종류(소규모 쌈지공원 vs. 대형 도시공원)를
구분하지 않아 실제 냉각 효과를 과소평가했을 수 있다.
향후 연구는 동(洞) 단위 GIS 분석으로 이를 보완해야 한다."
```

# 5-9. 흔한 실수 ❌ & 윤리 — 논문 작성

**흔한 실수 ❌**
- Results에 해석 쓰기 ("유의미하게 낮았다" → Discussion 몫)
- Discussion을 결과 반복으로 채움 → *왜 그런가*가 없음
- Abstract를 Introduction처럼 씀 → 방법·결과·결론 다 있어야 함
- 한 문단에 인용 없이 3문장 이상 → **표절 위험**

**연구 윤리 핵심 3가지**
1. **표절 금지**: Turnitin 또는 Grammarly 표절 검사 → 제출 전 필수
2. **데이터 조작 금지**: 결과가 안 좋아도 그대로. 데이터 삭제·수정은 연구 부정직(research misconduct)
3. **인용 정확성**: 읽지 않은 논문 인용 금지. 2차 인용 시 "as cited in" 명시

# 5-11. 🎓 실전 꿀팁 모음 — 논문 작성

- **쓰는 순서**: Methods → Results → Discussion → Introduction → Abstract. 서론을 처음에 쓰면 전체 방향이 흔들린다. Discussion 쓰고 나서야 "내가 뭘 말하려 했는지"가 확실해진다.
- **Abstract 5문장 공식**: ①배경 1문장 ②목적 1문장 ③방법 1문장 ④결과 1문장 ⑤결론/시사점 1문장. 250단어 넘지 말 것.
- **CARS 모델**: Move 1(중요성) → Move 2("드물다/연구되지 않았다") → Move 3("본 연구는") 3단계 서론 구조. 자연계·사회계 모두 통용.
- 결과 섹션에는 **해석을 쓰지 않는다**. "공원 면적이 넓을수록 열사병이 적었다(r=−0.68, p<0.01)"까지만. "이는 중요한 의미를 지닌다"는 Discussion으로.
- **Hemingway Editor** (hemingwayapp.com): 문장 가독성 채점 도구. Grade 8 이하 = 좋은 학술문. 장문 문장 자동 표시.
- **DeepL Write** 또는 **Grammarly**: 영어 논문 교정. 단, AI 교정 사용 시 Additional Info에 명시하는 것이 학교 정책에 따라 요구될 수 있음.
- 논문 피드백은 **최소 2명**: 학교 선생님(내용) + 원어민 또는 영어 잘하는 친구(언어). 멘토에게 Methods만 먼저 보내서 "재현 가능한가" 1차 검토 요청.
- 논문 완성 후 **Research Journal에 최종 반성글** 작성: "가장 힘들었던 순간", "다음에 바꿀 것". 이게 Common App 에세이 1차 원고가 된다.

# 6. 연구 경험 → 입시 서사 연결

## 에세이에서 연구를 어떻게 쓰는가

**틀린 방법 ❌**
> "저는 서울 공원 면적과 열사병의 상관관계를 연구했습니다. 결과는 r=−0.68이었고 p<0.01이었습니다."

**맞는 방법 ✅ (Common App 에세이 발췌형)**
> "데이터를 처음 돌렸을 때 r=0.02가 나왔다. 3주 동안 잘못된 가설을 붙잡고 있었다는 걸 그때 알았다. 노트북을 덮고 싶었지만, 그날 밤 데이터 전처리 로그를 다시 보다가 단위 환산 오류 하나를 찾았다. 수정 후 r=−0.68. 그 순간을 나는 아직도 기억한다."

→ **과정, 감정, 전환점** = 에세이가 읽히는 이유

# 6-2. 🎓 실전 꿀팁 모음 — 연구 → 입시 연결

- **Common App Additional Info 칸** (650단어): 논문 제목 + GitHub 링크 + 한 줄 요약. 에세이 아닌 곳에서 결과 수치 직접 제시.
- **Activity List**: 연구를 독립 항목으로. "Independent Research — [제목], [기간], [산출물: 논문/발표]" 형식.
- 연구 도중 **콜드 메일로 교수 멘토 확보했다면** → "Research Mentor: Prof. [이름], [대학]" → Activity List 설명 줄에 추가.
- **추천서**: 연구를 가장 가까이 지켜본 교사 또는 멘토가 쓰는 추천서 > 가장 좋은 성적의 과목 담당 교사 추천서. 연구 과정의 구체적 기여를 증언해줄 수 있는 사람 선택.
- **인터뷰 준비**: 다수 아이비는 동문 인터뷰 있음. "연구 중 가장 어려웠던 점"은 단골 질문. Research Journal이 있으면 즉시 답변 가능.
- 연구 제목을 **영어 + 한국어** 모두 준비. 국내 대회(한국청소년과학탐구대회) + 미국 대입 동시에 쓸 수 있음.
- 결과가 "no significant finding"이어도 **에세이 소재로는 오히려 강력**. "나는 틀렸고, 그래서 배웠다"는 사정관이 원하는 서사.
